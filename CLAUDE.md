# Картография коллапса · Web-HGIS атлас (1926–1939)

Школьный исследовательский проект (НИШ Астана, 11F: Жагиппаров Ализар, Утесеитов Али; руководитель Ғазиз Ақтоты Ғазизқызы). Проект прошёл на сетевой (областной) этап РКНП. Сайт — практическая часть научной работы «Картография распада», поэтому любая цифра и формулировка на сайте должна быть защитима перед жюри.

Прод: https://asharshylyk-full.vercel.app — деплоится автоматически из ветки `main` репозитория `uteseitovali/asharshylyk` (Vercel + GitHub). Пуш в любую другую ветку даёт preview-URL Vercel — используй это для проверки перед слиянием в `main`.

## Архитектура

Статический сайт без сборки, без npm, без env-переменных. Три файла:

- `index.html` — разметка, весь CSS, подключение скриптов (`/data.js?v=N`, `/app.js?v=N`, Chart.js 4.4.4 и canvas-confetti 1.9.3 локально из `libs/`).
- `data.js` — данные как JS-присваивания: `window.__KZ_HIST__` (`"1926"`: 8 округов, `"1939"`: 12 областей; каждый элемент `{p: свойства, g: GeoJSON-геометрия}`), `window.__WORLD__` (подложка карты мира; генерируется `scripts/build_world.js`, не править вручную), `window.__MAUP__` (матрица 8×12: `m`, `a26`, `a39`, `interpKaz`, `interpTot`, `resid`, `shareShift`).
- `app.js` (~260 КБ, плотный «минифицированный» стиль: цепочки через запятую, `!1`/`!0`, `1 / 0`). Основные блоки по порядку: `I18N` (ru/en/kz) → `t()/tf()/tr()/pName()/pDesc()/pType()` → `setLang()` → `SCHOOLS`, `CAMPS`, `REVOLTS`, `FLOWS`, `FAMINES`, `STORY`, `QUIZ` → база знаний ИИ (`kbRu/kbEn/kbKz`) → проекции (`albers`, `equalEarth`) → карта Казахстана (`renderKz`, `metricDef`, `renderStats`, `openRegion`, `drawChart`) → StoryMap (`storyStart/storyStep`) → карта мира → историография → `BIBLIOGRAPHY` → таблица и MAUP-калькулятор (`buildTable`, `calcMaup`) → квиз → ИИ-ассистент (WebLLM в браузере, загружается с esm.run только по кнопке «Загрузить модель», `SYS_RU/SYS_EN/SYS_KZ`, `retrieve`, `ask`) → `renderAbout`.
- Вкладки в `index.html`: `#v-kz`, `#v-world`, `#v-schools`, `#v-biblio`, `#v-data`, `#v-quiz`, `#v-ai`.

## Правила работы

1. **Три языка всегда.** Любая новая видимая строка добавляется в `I18N.ru`, `I18N.en` и `I18N.kz` (одинаковые ключи), а объекты данных получают блоки `ru/en/kz`. Числа форматируются через `fmtN` (целые) и `fmtD` (дробные): для ru и kz — пробел-разделитель тысяч и десятичная запятая (`ru-RU`; у Chrome нет данных локали `kk`, он подставляет английский формат), для en — `en-US`. Не используй `toFixed` для видимых чисел. Не оставляй хардкод `"en" === LANG ? X : Y` без ветки `kz`.
2. **Не переформатируй `app.js` целиком** (никаких prettier на весь файл) — точечные правки, иначе дифф нечитаем.
3. **Ни одного выдуманного исторического числа.** Каждое число — с источником (перепись 1926/1939 через Демоскоп, Cameron 2018, Алексеенко 2000, Абылхожин–Козыбаев–Татимов 1989, Омарбеков 1997/2003 и т. д. — см. список литературы в работе). Если источник недоступен — остановись и спроси, не подставляй «правдоподобное» значение.
4. **Различай уровни утверждений** (как в работе): опубликованный факт / расчётное значение модели / гипотеза. Оценки помечаются «≈» и диапазоном. Границы 1926 и 1939 — опорная реконструкция на геометрии geoBoundaries, не архивный кадастр.
5. **Согласованность с текстом работы.** Сайт должен совпадать с поданной работой: потери 1,3–2,3 млн (безвозвратные; Алексеенко 1,5–1,84 млн), «более 370 выступлений» (Омарбеков), 8 округов / 12 областей / 96 пересечений (на сайте: «матрица 8 × 12: 96 пар „округ — область“, из них 37 с ненулевой площадью пересечения»), доля казахов ≈38 % (1939), апробация N = 32. Доля казахов в 1926 г. на сайте — ≈58,5 % по источнику (Асылбек, Асылбекова, 2014; перепись 1926 г., Демоскоп: 3 627,6 из 6 198,5 тыс. без Каракалпакской АО), а не «>60 %» из текста работы; население 1926 г. — ≈6,2 млн. Гипотеза (дословно, с. 12): «Гипотеза состоит в том, что наиболее тяжелые потери приходились на районы традиционного скотоводства, тогда как статистический прирост в промышленных центрах мог быть следствием принудительной и организованной миграции». Если что-то на сайте расходится с работой — сначала сообщи, не правь молча.
6. **Кэш:** после любой правки `app.js` или `data.js` увеличь `?v=` в `index.html` у обоих скриптов.
7. **Проверка после каждого шага:** `node -c app.js`; `node -e "global.window={};eval(require('fs').readFileSync('data.js','utf8'))"`; сверка ключей I18N (у ru/en/kz одинаковое число ключей); затем ручной просмотр в браузере во всех трёх языках.

## Локальный запуск

Скрипты подключены абсолютными путями (`/app.js`), поэтому двойной клик по `index.html` НЕ работает. Запускать из корня репозитория:

```
python -m http.server 8000
```

и открыть http://localhost:8000. ИИ-ассистенту нужен WebGPU (Chrome/Edge) и загрузка модели ~1–2 ГБ — для остальных вкладок он не нужен.

## Git

Репозиторий уже подготовлен: тег `school-stage` стоит на версии, которая была на сайте до начала доработок (точка отката), рабочая ветка — `regional-stage`. Работать в ней, коммитить маленькими шагами с понятными сообщениями, пушить ветку (`git push -u origin regional-stage`) и проверять preview-URL Vercel. В `main` — только проверенное. Не коммитить временные файлы (`*.patch`, черновики).

Служебные файлы (`CLAUDE.md`, `PROMPTS.md`, `docs/`, `scripts/`) исключены из деплоя через `.vercelignore` — на публичный сайт они не попадают. Если создаёшь новый служебный файл в корне — добавь его туда же.
